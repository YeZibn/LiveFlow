## Context

当前 MySQL 用户名列使用 `ascii_general_ci`，登录 Service 会转换大小写。账号登录、JWT、Redis 单会话与 Vue 首页已经实现。注册业务将接入现有 MVC 和同源认证流程。HTTP 与数据库字段以 `docs/design/auth/api.md` 和 `docs/design/auth/database.md` 为准。对外行为见 [认证规格变更](specs/user-auth/spec.md)。

## Goals / Non-Goals

**Goals**

- 将账号原样校验、数据库唯一约束、登录查询和前端输入统一为精确匹配。
- 完成 Vue 注册表单、后端接口和测试环境切换，保留原有认证模块的职责分工。
- 用清楚的中文注释说明跨层契约，并解释并发、限流和凭证处理的关键判断。

**Non-Goals**

邮箱绑定、自助密码重设与直播间创建属于后续变更。

## Decisions

### 在现有认证模块显式创建账号

Controller 对注册请求做严格 JSON 结构检查，并调用 Service。Service 先校验账号名和新密码，再执行来源限流，最后通过现有 Argon2id 参数生成哈希并调用 Mapper。Mapper 以绑定参数插入一行并返回自增主键，时间使用 UTC 毫秒。一次成功插入构成账号创建，确认提交后 Controller 返回 `201`、账号摘要及 `Cache-Control: no-store`。注册操作只写账号数据，现有登录入口负责会话建立。

先查询“账号是否存在”只能提供瞬时结果，两个请求仍可能同时看到空值。注册直接插入，由 `uk_users_username` 裁决，只有用户名唯一键冲突映射成 `AUTH_USERNAME_ALREADY_EXISTS`，其他存储故障沿用认证暂不可用响应。

### 用户名校验与存储采用一套精确规则

注册和登录复用同一条用户名格式规则，原始字符串用于查重、SQL 等值查询、登录限流和响应。Flyway V3 将 `users.username` 修改为 ASCII `ascii_bin`，沿用现有索引。这样等值查询可以直接使用索引，两种大小写拼写对应不同 `userId`。新密码的复杂度检查放在注册业务规则中，登录凭现有哈希验证，并继续保留现有请求大小边界。昵称规则由个人主页负责。

### 注册限流以来源固定窗口裁决

Redis 使用独立的注册来源键。在一次脚本执行中检查剩余额度、计数并设置首次过期时间。超限时返回该窗口剩余时间，向上取整为整数秒后写入 `Retry-After`。只对字段校验通过的请求计数，包括完全同名的有效提交。限流位于哈希计算之前，避免请求超限后继续消耗 Argon2id 的计算资源。使用项目现有的可信来源地址提取方式，登录限流规则继续负责登录。

### 前端直接接入注册接口

Vue 在当前登录入口切换注册表单，继续复用同源认证客户端和 CSRF 初始化。账号、密码和确认密码各自有标签。两个显隐按钮为独立的非提交按钮，支持键盘操作并提供可读状态。页面使用与服务端一致的字段范围，密码确认仅留在前端。注册成功时清空密码、预填原样账号并切回登录。失败时保留表单，显示字段或全局错误，`429` 按响应等待时间提示。提交期间防止重复发送，传输超时后由用户确认或尝试登录。

### 代码注释与组织

Java 的新增跨层入口补中文 Javadoc，说明职责、参数、返回值、副作用和适用异常。TypeScript 的注册客户端和表单关键入口说明输入、返回及失败语义。Lua 和 Java 关键分支注明计数边界、大小写语义、数据库冲突裁决和密码哈希顺序的原因。账号和密码使用明确命名，涉及明文的请求对象采用现有敏感信息处理方式，日志避免输出密码、哈希、Cookie 和令牌。

## Risks / Trade-offs

- 并发提交同名账号 → 依赖数据库唯一约束，按键冲突返回确定的结果。
- 账号已写入但响应丢失 → 用户可以直接尝试登录，重复提交仍由唯一约束保护。
- 共享网络下短时集中注册 → 使用可配置的注册窗口和等待时间，额度默认按已确认的接口设计。

## Migration Plan

按 `docs/design/auth/database.md` 的开发与测试数据重建流程操作。暂停目标开发环境认证写入，以已核定的测试账号 ID 为范围清理对应 Redis 会话和 MySQL 账号，个人资料随账号外键级联清理，保留自增序列。随后执行 V3、启动新版并通过页面重新注册。V3 专注于结构变更，数据清理由目标开发环境的切换步骤执行。整个切换使用新版的精确匹配规则。
