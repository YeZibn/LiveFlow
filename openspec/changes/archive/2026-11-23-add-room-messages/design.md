## Context

现有房间路由按 UUID 加载详情并复用 `withAccess`，已登录用户可以分享链接。实际房间页的右侧弹幕区目前为占位，现有 WebSocket 端点仅作本地探测。 [房间页实现](../../../../frontend/src/room/RoomView.vue) · [弹幕设计](../../../../docs/design/room-messages/design.md) · [接口约定](../../../../docs/design/room-messages/api.md) · [状态与并发约定](../../../../docs/design/room-messages/storage.md)

## Goals / Non-Goals

**Goals**

- 在既有认证及 Maven 模块结构内交付真实的房间内收发链路和完整 Vue 面板。
- 让提交、受理确认、接收、重试与重连拥有明确的边界，验证实际运行下的归属隔离和并发裁决。

**Non-Goals**

- 播放、画面滚动弹幕、历史、离线补发、在线人数和跨实例广播留给后续变更。

## Decisions

### HTTP 负责提交，WebSocket 负责接收

两个 MVC 路由沿用 Bearer、CSRF、UUID 验证与当前会话。消息发送的确认走 HTTP，列表只消费实时广播。WebSocket 升级入口按路径和来源限制，连接升级后处于待鉴权状态。Redis 保存有 TTL 的票据摘要和绑定信息，原子消费后复查会话。确认成功后先排入 `ready` 再参与广播。握手首帧超时、心跳、当前会话复查、关闭回调均走统一清理路径，避免留下连接及待发送队列。

### 保持接受裁决和连接写入独立

核心业务按账号串行裁决重复提交和滚动额度，并与房间分发配合确保一次接受、一次广播。使用有界内存存放去重记录和待发送队列。去重空间耗尽时拒绝新的提交并保留尚有效的记录。房间内按接受顺序入队，每条连接串行写网络，入队失败或写入超时只关闭对应连接。HTTP 成功在本机接受和入队完成后返回。

### 让 Vue 面板独立承担弹幕交互

在详情成功后挂载以房间与会话为生命周期的弹幕面板，保留现有页面布局和导航。桌面右列和移动端下方使用同一组件，包含状态、独立可滚动的消息列表和发送表单。显示连接中、可发送、重连和失败反馈。消息到达时仅在用户停留在底部附近时继续跟随，正在向上阅读时保留当前位置。复用 `withAccess` 请求票据和发送，使用同源 WS 地址。网络失败采用有限退避并提供手动重连入口，重连获取新 Ticket。取消过期计时和回调。提交立即保存输入快照及客户端 ID，响应确认只更新它对应的提交。发送不确定时由用户手动重试，保留原 ID 和正文。走纯文本插值并处理中文输入法组字。

### 注释交付

Java Controller、Service、Redis 仓储和前端请求入口补齐职责、参数、返回值及适用异常。关键语句的注释解释票据为何先消费再复查会话、`ready` 与注册的顺序、判重和限流的裁决边界、慢连接关闭、旧回调失效，以及发送重试为何复用原 ID。

## Risks / Trade-offs

- 断线或进程重启可能错过消息 → 明确实时收发边界，页面保留本会话已收到的内容，展示暂不可用状态及恢复入口。
- 客户端未收到发送响应 → 保留提交快照和标识，同实例去重保留窗口内安全复用，过期或重启后提示可能重复。
- 积压导致队列增长 → 限制连接、去重容量与单连接队列，隔离慢写入，核对注销与定时任务释放。

## Migration Plan

本版增加 Redis 短期票据和内存状态，直接复用房间表。部署时先让 API 和 WebSocket 路径可用，再发布 Vue；本地继续使用 Vite 的 `/ws` 代理。回退时恢复旧版房间页与服务，连接关闭并释放内存状态，已签发票据依 TTL 清理。
