## Purpose

让 LiveFlow 已登录用户在同一直播间发送和实时接收纯文本弹幕，明确消息受理、短期去重、房间隔离和页面恢复的行为。

## ADDED Requirements

### Requirement: 房间接收连接鉴权

系统 MUST 提供 `POST /api/v1/rooms/{roomId}/ws-ticket`，校验 Bearer、CSRF、当前会话和房间 UUID，成功返回不可缓存的 `200`、`ticket` 和 `expiresIn`。票据绑定账号、会话及房间，默认 30 秒有效且只可消费一次。`/ws/rooms` MUST 校验来源，默认在 5 秒内接收首帧 `auth`，验证票据与当前会话后先发送 `ready` 再发送房间消息。就绪连接 MUST 周期复查原会话，默认每 15 秒一次。无法确认会话时关闭连接。

#### Scenario: 有效票据建立连接

- **WHEN** 已登录用户为存在的房间申请票据，并从允许来源在首帧提交
- **THEN** 服务端以绑定的 UUID 返回 `ready`，该连接可以接收对应房间的后续消息

#### Scenario: 拒绝无效鉴权和重复消费

- **WHEN** 来源未获允许、首帧无效或超时、票据过期，或两个连接并发消费同一票据
- **THEN** 无效请求无法入房，并发消费最多一个连接取得资格

#### Scenario: 登录会话被替换或无法确认

- **WHEN** 连接建立后会话在其他浏览器被替换，或复查遇到认证存储故障
- **THEN** 旧会话的 HTTP 发送按认证契约拒绝，旧连接在复查确认失效或无法确认时关闭

### Requirement: 发送弹幕及短期去重

系统 MUST 提供 `POST /api/v1/rooms/{roomId}/messages`。写请求要求有效 Bearer、CSRF 和存在的房间，JSON 正文只接受标准小写 UUID v4 的 `clientMessageId` 和字符串 `content`。原始正文拒绝控制字符、行段分隔符和未配对代理项，去除首尾 Unicode 空白后为 1–100 个码点。服务端接受后 MUST 返回不可缓存的 `200`、`messageId` 和 UTC `sentAt`。同一实例按账号共享额度，默认滚动 10 秒最多接受 5 条。已接受提交默认保留 60 秒，以登录会话、房间 UUID 和客户端标识判重。

#### Scenario: 接受有效提交

- **WHEN** 有效会话为存在的房间提交合法正文且账号额度充足
- **THEN** 服务端接受一次提交，返回服务端生成的消息 UUID 和三位毫秒 UTC 时间，对应房间获得同一消息

#### Scenario: 并发重试和正文冲突

- **WHEN** 去重窗口内重复提交同一请求标识，或同一标识携带不同的规范化正文
- **THEN** 相同提交均返回原结果，只广播和计入额度一次，正文不同时返回 `409 MESSAGE_ID_CONFLICT`

#### Scenario: 账号共享发送额度

- **WHEN** 同账号通过多标签页或不同房间达到了当前发送额度
- **THEN** 新提交返回 `429 MESSAGE_RATE_LIMITED` 及整数秒 `Retry-After`，不会广播

#### Scenario: 拒绝无效或无法受理的请求

- **WHEN** 请求输入、认证或 CSRF 无效，房间不存在，或服务端无法接受新消息
- **THEN** 接口按契约返回相应的 `400`、认证错误、`404` 或 `503`，该次拒绝不产生广播

### Requirement: 本机同房间实时分发

服务端 MUST 按房间接受顺序向该房间当时就绪的连接分发 `message`，各连接获得相同的 `messageId`、`content` 和 `sentAt`。HTTP 成功确认本机接受和分发入队。断线或过载的连接可能错过消息，重连后只接收新的广播。

#### Scenario: 同房间分发和跨房间隔离

- **WHEN** A 和 B 已就绪且同处一间房，C 在另一间房，A 发送一条消息
- **THEN** A 和 B 各接收一次相同数据，C 收不到该消息

#### Scenario: 慢连接隔离

- **WHEN** 某连接写入持续阻塞，达到队列或网络写入限制
- **THEN** 服务端关闭该连接，同房间其他正常连接继续按接受顺序接收

### Requirement: 房间弹幕面板与恢复

房间页 MUST 提供连接状态、正文输入、发送按钮、发送反馈及消息列表。只有收到当前房间的 `ready` 后才可发送。列表 MUST 由下行 `message` 更新，纯文本展示正文和时间，最多保留最近 100 条。切换房间或会话时清理旧列表、待提交和连接任务。输入框 MUST 避免中文输入法组字时误发送。

#### Scenario: 广播早于发送响应

- **WHEN** 用户先收到同一消息的下行广播，随后才收到 HTTP 成功
- **THEN** 列表只增加一项，HTTP 响应只更新该次提交状态

#### Scenario: 发送结果不明确

- **WHEN** 请求超时或响应丢失，用户选择再次提交原正文
- **THEN** 页面保留原正文和标识并提示结果不确定，手动重试复用原标识，重连不会自动发送

#### Scenario: 重连、刷新与换房

- **WHEN** 用户断线重连、刷新页面或切换房间与会话
- **THEN** 同页同会话重连申请新票据并保留已收到的列表，刷新或切换后清空，迟到的旧事件不进入当前面板
