## Context

现有 `room-creation` 规格和已发布数据库结构使用自增标识。Vue 已有登录恢复及按会话渲染个人主页的入口。此变更按已确认的访问规则扩展房间模块。 [房间设计](../../../../docs/design/room/design.md) · [接口契约](../../../../docs/design/room/api.md) · [数据库设计](../../../../docs/design/room/database.md)

## Goals / Non-Goals

**Goals**

- 保留原有房间及归属，统一创建、本人查询、详情和页面 URL 的外部标识。
- 在已有登录体系内支持进入、分享和刷新，覆盖数据库、MVC 与 Vue。

**Non-Goals**

- 播放、开播状态、列表、房间成员、WebSocket 和弹幕收发留给后续变更。

## Decisions

### UUID 作为稳定对外标识

保留内部主键，使用 `room_uuid` 唯一索引提供按 UUID 的等值查询。增列、Java 随机 UUID 回填、必填约束按 Flyway 版本分步执行。回填只更新空值行。创建时由 Java 生成 UUID，插入和本人回读在同一事务。房主唯一冲突保持 `409`。UUID 唯一冲突时结束失败事务，生成新值并开启一次重试事务；其他存储错误和第二次 UUID 冲突映射为 `503 ROOM_SERVICE_UNAVAILABLE`。

### 在现有安全链上增加只读详情

按 HTTP 方法精确放行详情路径到认证处理。Controller 先使用严格的小写 UUID v4 路径格式，Mapper 按 UUID 只读详情字段。现有本人查询仍按调用者归属。详情访问复用 Bearer 与 Redis 当前会话校验；创建继续校验 CSRF。固定错码区分格式无效、房间不存在和存储故障。

### 复用认证入口渲染房间页

使用页面路径保留目标房间。会话未建立时由现有登录入口处理，登录和会话恢复完成后渲染对应房间。页面按房间 UUID 及会话隔离读取结果，确保旧响应在路由或会话切换时失效。现有首页及开发检查入口沿用。服务器应为直接访问及刷新房间页提供 SPA 入口，API 仍走后端。页面复用共享样式，桌面用双栏，手机用上下布局。复制同源房间 URL 并反馈剪贴板结果。

## Risks / Trade-offs

- 旧写入端无法提供 UUID → 暂停旧版创建流量，完成迁移后同步发布 API 和 Vue。
- 新增深链接可能在生产环境刷新时报错 → 核对静态服务的 SPA 回退与 `/api/` 转发规则。
- UUID 冲突与旧房主冲突语义不同 → 按约束名区分并验证冲突分支。

## Migration Plan

保留 V4，新增版本依次执行带唯一索引的可空列、Java 回填和非空约束。验证 V4 有数据的升级路径和全新库安装。保留已经分配的 UUID 和房间记录。若回退到旧版应用，停用旧版创建，恢复 UUID 版本后再开放写入。
