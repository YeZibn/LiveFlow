## Context

当前 `CookieCsrfTokenRepository` 提供同源 SPA 的双提交 CSRF，接口在认证状态变化后重新初始化。Bearer 通过 JWT 和 Redis 当前会话鉴权。刷新与退出由 Refresh Cookie 和会话 Lua 脚本控制。前端同源标签页使用 Web Locks 协调认证写操作。 [现行接口](../../../../docs/design/auth/api.md#cookie-与-csrf) · [生产加固设计](../../../../docs/design/auth/security.md)

## Goals / Non-Goals

**Goals**

- 将匿名和认证态 CSRF 分别绑定到短期预会话和当前登录会话。
- 使所有适用写请求在副作用之前完成 CSRF 校验，并保留 Refresh Token 原有的轮换、重放和指定会话撤销语义。
- 支持多实例与浏览器重载后的安全补领。

**Non-Goals**

- Refresh Token 持有者绑定、JWT 格式调整和登录并发规则改造。
- 新增 MySQL 表或 Redis 会话字段。

## Decisions

### 使用分用途签名双提交

由服务端统一处理匿名预会话和认证态 CSRF 的签发与校验。两种用途使用不同的签名上下文和 Cookie。签名采用 HMAC-SHA-256，输入包含无歧义编码的版本、密钥标识、用途、绑定值和随机值。拒绝不规范编码、缺项及未知密钥标识，使用恒定时间比较签名。匿名预会话采用受完整性保护的随机标识和绝对截止时间，实施默认值取设计推荐的 15 分钟。认证态绑定当前会话 `sid`，Cookie 截止取 Redis 会话剩余时间。现有 Redis 会话结构已承载登录生命周期。按 Token 存储同步器状态会为既有会话引入额外存储和续期协调。 [凭证格式与 Cookie](../../../../docs/design/auth/security.md#凭证与生命周期)

### 按凭证来源设置写请求边界

- 注册和登录在业务处理前验证匿名 CSRF。登录在 Redis 建立新会话后，随同响应设置认证态 CSRF Cookie，并清除匿名 Cookie。
- Bearer 业务写路由在身份校验之后、首次执行副作用之前验证认证态 CSRF。枚举路由并保留拒绝兜底，明确首次 Servlet 请求和内部异步响应重派发的边界，避免中间阶段重复执行或漏查。
- 刷新与退出从 `lf_refresh` 取得验签所需的候选会话。CSRF 通过后才调用现有原子变更。若在刷新前先查询并要求 Refresh 摘要仍是当前值，已消费的凭证无法触发现有撤销分支。
- 生产写请求和签发入口检查配置的精确 Origin，缺少时用 Referer 的 Origin，拒绝明确不匹配及 `null`。缺少两个来源头时仍执行入口原有的认证与 CSRF 要求。保持同源访问边界。 [入口顺序](../../../../docs/design/auth/security.md#http-接口与校验顺序)

### 认证态补领使用只读会话快照

补领有显式 Bearer 时，以 JWT 身份及匹配的 Redis 当前会话获取截止时间。无 Bearer 时，从同一次只读 Redis 快照核对当前会话、有效期和当前 Refresh 摘要，签发结果绑定已核对的会话。已消费摘要无法补领。前端为刷新补领时不发送 Bearer。

Vue 按入口选择请求头对应的 CSRF Cookie。认证态 Cookie 存在时直接走刷新 POST。缺失时才在认证操作锁内补领。补领失败和刷新响应不明确都沿用相应会话的错误处理。旧响应或标签页标记只能影响前端协调，授权仍以当前服务端会话为准。 [恢复及并发](../../../../docs/design/auth/security.md#重放检测恢复和并发)

## Risks / Trade-offs

- **签发与轮换之间会话可能变化** → 签发使用读取到的会话绑定与截止时间。随后的写请求在各自入口重新校验，Redis Lua 仍负责原子裁决。
- **同时丢失 CSRF Cookie 且 Refresh Token 已消费** → 补领失败后要求重新登录。没有通过 CSRF 校验的刷新无法触发重放撤销。
- **多个实例的签发密钥可能配置不一致** → 同环境实例共享独立密钥配置。轮换按先分发验签密钥、后启用签发、最后退役旧密钥的顺序处理。
- **旧前端仍使用匿名 GET 和旧 Cookie** → 前后端协调切换，提示旧页面重新加载。

## Migration Plan

1. 为所有接流实例配置公开 Origin、同环境共享的 CSRF 密钥与当前密钥标识，生产使用 `__Host-` Cookie。本地回环 HTTP 通过显式配置使用开发名称。
2. 将新前端与新接口在同源入口协调切换。确保接流实例统一使用新契约。现有有效会话可用当前 Refresh Cookie 只读补领。
3. 回退时成对切回旧前后端契约并使旧页面重新加载。会话和账号数据可继续使用。 [发布与回退](../../../../docs/design/auth/security.md#生产配置与切换)
