## MODIFIED Requirements

### Requirement: 发送弹幕及短期去重

系统 MUST 提供 `POST /api/v1/rooms/{roomId}/messages`。写请求要求有效 Bearer、CSRF 和存在的房间，JSON 正文只接受标准小写 UUID v4 的 `clientMessageId` 和字符串 `content`。原始正文拒绝控制字符、行段分隔符和未配对代理项，去除首尾 Unicode 空白后为 1–100 个码点。服务端接受后 MUST 返回不可缓存的 `200`、`messageId` 和 UTC `sentAt`。同一实例按账号共享额度，默认滚动 10 秒最多接受 5 条。已接受提交默认保留 60 秒，以登录会话、房间 UUID 和客户端标识判重。新提交受理前 MUST 读取可信认证账号的显示名；查无账号按会话失效处理，读取故障返回 `503 ROOM_MESSAGES_UNAVAILABLE`，此请求不消耗额度且不广播。命中已受理记录时 MUST 按原记录裁决。

#### Scenario: 接受有效提交

- **WHEN** 有效会话为存在的房间提交合法正文且账号额度充足
- **THEN** 服务端接受一次提交，返回服务端生成的消息 UUID 和三位毫秒 UTC 时间，对应房间获得同一消息

#### Scenario: 并发重试和正文冲突

- **WHEN** 去重窗口内重复提交同一请求标识，或同一标识携带不同的规范化正文
- **THEN** 相同提交均返回原结果，只广播和计入额度一次，正文不同时返回 `409 MESSAGE_ID_CONFLICT`

#### Scenario: 账号共享发送额度

- **WHEN** 同账号通过多标签页或不同房间达到了当前发送额度
- **THEN** 新提交返回 `429 MESSAGE_RATE_LIMITED` 及整数秒 `Retry-After`，不会广播

#### Scenario: 拒绝无效或无法受理的请求

- **WHEN** 请求输入、认证或 CSRF 无效，房间不存在，或服务端无法接受新消息
- **THEN** 接口按契约返回相应的 `400`、认证错误、`404` 或 `503`，该次拒绝不产生广播

#### Scenario: 资料读取故障时查询已受理提交

- **WHEN** 使用相同 ID 和相同正文重试已受理的请求，同时发送者资料不可读取
- **THEN** 在原受理记录有效时仍返回原回执，本次不再广播或消耗额度

### Requirement: 本机同房间实时分发

服务端 MUST 按房间接受顺序向该房间当时就绪的连接分发 `message`，各连接获得相同的 `messageId`、`senderName`、`content` 和 `sentAt`。`senderName` MUST 取受理时使用的发送者显示名，有昵称时取昵称，空昵称或无资料时取原拼写用户名。帧 MUST 隐藏账号 ID。HTTP 成功确认本机接受和分发入队。断线或过载的连接可能错过消息，重连后只接收新的广播。

#### Scenario: 同房间分发和跨房间隔离

- **WHEN** A 和 B 已就绪且同处一间房，C 在另一间房，A 发送一条消息
- **THEN** A 和 B 各接收一次包含同一发送者显示名的数据，C 收不到该消息

#### Scenario: 慢连接隔离

- **WHEN** 某连接写入持续阻塞，达到队列或网络写入限制
- **THEN** 服务端关闭该连接，同房间其他正常连接继续按接受顺序接收

#### Scenario: 发送者修改昵称后再次发送

- **WHEN** 用户以昵称或原拼写用户名发送消息，保存新昵称，再发送另一条消息
- **THEN** 新发送的消息显示新的昵称，已发送消息继续显示当时的名称

### Requirement: 房间弹幕面板与恢复

房间页 MUST 提供连接状态、正文输入、发送按钮、发送反馈及独立滚动的消息列表，发送区固定在面板底部。只有收到当前房间的 `ready` 后才可发送。列表 MUST 由下行 `message` 按接收顺序更新，最多保留最近 100 条。每条消息 MUST 在有空间时同一行展示浏览器本地 24 小时制 `HH:mm:ss`、发送者和正文，空间不足时自然换行，名称和正文以纯文本渲染。切换房间或会话时清理旧列表、待提交和连接任务。输入框 MUST 避免中文输入法组字时误发送。

#### Scenario: 广播早于发送响应

- **WHEN** 用户先收到同一消息的下行广播，随后才收到 HTTP 成功
- **THEN** 列表只增加一项，HTTP 响应只更新该次提交状态

#### Scenario: 发送结果不明确

- **WHEN** 请求超时或响应丢失，用户选择再次提交原正文
- **THEN** 页面保留原正文和标识并提示结果不确定，手动重试复用原标识，重连不会自动发送

#### Scenario: 重连、刷新与换房

- **WHEN** 用户断线重连、刷新页面或切换房间与会话
- **THEN** 同页同会话重连申请新票据并保留已收到的列表和草稿；刷新或切换后清空，迟到的旧事件不进入当前面板

#### Scenario: 消息在阅读和跟随时到达

- **WHEN** 新消息在列表底部跟随或用户上翻阅读时到达
- **THEN** 在底部时滚动跟随，上翻阅读时保留仍可见条目的位置并显示「查看新消息」，点击后回到底部
