## Context

当前前端由 `AuthView.vue` 在同一页面承载登录表单和已登录区域，`useAuth.ts` 管理会话恢复、Access Token 与当前用户。Spring Security 已校验 JWT 和 Redis 中的当前会话，现有 `/api/v1/auth/me` 从账号表读取身份摘要。项目设计位于 `docs/design/profile/`，本变更的动机见 [提案](proposal.md)，对外行为见 [资料规格](specs/user-profile/spec.md)。

## Goals / Non-Goals

**Goals**

- 按现有 MVC 模块落地资料读取、校验、事务保存和 MySQL 迁移。
- 上线完整的 Vue 查看与编辑流程，并直接接入新接口、复用现有认证状态。
- 用明确命名、完整方法文档和关键注释说明跨层契约及并发处理原因。

**Non-Goals**

公开资料页、头像上传和直播间创建属于后续变更。

## Decisions

### 资料存储按账号一对一

按 `docs/design/profile/database.md` 在 `liveflow-core` 新增 Flyway V2，`user_id` 作为主键和关联账号的外键。读取从账号表左连接资料表，资料缺省时使用默认值。相比把展示字段加到账号表，独立表将资料写入与账号凭证管理分开，并允许已有账号在首次编辑时再落库。保存走单条 upsert，在同一事务内回读，以原子更新和主键约束处理并发首次保存。写入前规范化全部输入，提交后交付响应。

### 路由沿用现有认证和错误约定

`liveflow-api` 为两条路由显式启用认证，从已验证 JWT 的 `sub` 获取账号 ID。`PUT` 使用已有 CSRF 规则。请求的 JSON 类型和允许字段由资料入口严格检查，资料 Service 负责规范化、业务校验和数据库读写。把严格 JSON 检查限定在资料入口，可避免全局反序列化配置波及其他接口。错误遵循 `docs/design/profile/api.md`，认证错误交给现有机制，资料存储错误由资料接口映射。

### Vue 直接调用资料接口

已登录页面渲染独立的个人主页组件，当前用户和会话仍由同一份认证状态持有。资料客户端使用同源请求并复用现有 Bearer、CSRF 和一次性续期机制，按需扩展共享请求逻辑以处理 `PUT`。此次采用单一资料接口与 DTO，禁止引入旧接口别名、字段双写、兼容适配器或从认证摘要拼装资料页面的降级分支。内置头像按资料接口约定的键渲染。

### 保存状态与当前会话绑定

编辑表单维护暂存值，保存成功后用服务端响应更新展示并退出编辑。前端保存时禁止重复提交，服务端明确返回 Access Token 过期时仅在同会话续期后重发一次。网络结果不明确时保留表单，提供重新读取确认的路径。退出、被替换或身份切换后清理资料状态，使用现有会话标识或代次检查拒绝迟到结果。

## Risks / Trade-offs

- 两个标签页并发编辑 → 以最后一次成功提交的完整资料为准。使用数据库主键和单条写入保证字段不会混合，页面通过重新读取获取当前值。
- 资料保存前会话已被替换 → 由过滤链拒绝。已经通过鉴权的请求沿用现有请求边界，前端同时校验响应归属，避免旧结果覆盖新页面。
- 保存已提交但响应丢失 → 保留用户输入并允许重新读取确认，通过显式保存避免自动重发覆盖其他标签页的新数据。

## Migration Plan

发布时先完成 V2 再开放路由和页面。现有账号在首次读取时获得默认资料，首次保存时才创建资料行。需要回退应用时保留 V2 表与已保存的数据，恢复新版后可继续读取。
