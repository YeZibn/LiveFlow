## Context

历史 GET 已支持最近窗口与带上界的 `afterSeq` 范围读取。Vue 目前把实时帧和最近查询都并入同一个最多 100 条的列表。阅读锚点也依赖这份列表，超过上限的旧条目会被裁剪。详见 [弹幕 V2 设计](../../../../docs/design/room-messages/v2/design.md#进房历史回看与重连) 和 [行为规范](specs/room-messages/spec.md)。

## Goals / Non-Goals

**Goals**

- 以严格排他的房间序号游标读取上一页，复用当前鉴权、房间检查和一致性快照。
- 在回看、实时更新和重连同时发生时保持内容、游标和阅读位置一致。

**Non-Goals**

- 消息全文搜索、跨房间历史及跨页面保存阅读位置。
- 24 小时保留策略调整、数据库迁移及广播或发送链路改造。

## Decisions

### 延续现有历史 GET

`RoomMessageController` 归一化并校验参数，使最近页、向上页、范围补拉三种模式清晰互斥。保留已有字段和错误映射，只添加可空的 `nextBeforeSeq` 响应字段。现有 `afterSeq` 调用继续支持固定读取上界，反向游标按本页最小序号推进。

排他序号游标可以用同一个复合主键定位，能跨过缺号和已过期的边界记录。按页号和偏移量查询会受新入库及清理影响，位置可能移动，同时深页扫描量随偏移增加。 [接口定义](../../../../docs/design/room-messages/v2/api.md#查询历史)

### 在现有历史快照内完成倒序查询

`RoomHistoryService` 继续在同一事务内检查持久阻断、读取最大落库序号与消息页，并在一页内使用同一 UTC 截止时间。映射层以 `room_id` 等值和 `room_seq` 上界扫描主键。最近页及向上页按序号倒序读取 `limit + 1` 条，服务层先截取，再反转为升序。额外行只用于判断是否还有一页。现有范围补拉保持升序扫描及 `nextAfterSeq` 语义。 [查询和索引](../../../../docs/design/room-messages/v2/database.md#历史查询和分页)

### 分离跟随窗口和回看状态

- `roomMessagesClient.ts` 解析三种分页模式各自的游标、排序和序号边界。序号以规范十进制字符串传输，客户端按 `BigInt` 比较。
- `useRoomMessages.ts` 管理最近窗口和本次回看。最近窗口每次合并后取最新 100 条。离开底部时从当前已显示列表创建回看，第一页以其最小序号为边界，随后沿响应游标请求。共用按消息 ID 和序号去重的合并规则，历史冲突以持久记录为准。
- 最近刷新按房间、会话和连接代次隔离。向上查询按房间、会话和回看身份隔离，单次回看只允许一个在途；WebSocket 换代不使该请求失效。回看结束后释放历史页并作废在途结果，旧结果也不能覆盖换房或换会话后的状态。
- `RoomMessages.vue` 在触顶前的一小段距离触发查询，并提供键盘可达的加载和重试按钮。插入前记录可见项 ID、房间序号与屏幕位置，渲染后按 ID 或序号修复滚动位置。程序恢复锚点不触发加载。实时更新只在范围内作必要合并，较新项留在最近窗口，提示用户返回最新。解除 100 条裁剪而使用一个持续增长的实时列表，会让阅读时的内存用量随实时流量增长。

## Risks / Trade-offs

- **实时到达可能挤出最近页的部分历史** → 首次向上查询用实际列表的最小序号，不直接采用最近响应的上一页游标。
- **分页之间有过期或迟到记录** → 每页独立读取当前快照。只推进服务端返回的实际记录游标，重新读取相应范围时可以看到保留期内的迟到项。
- **实时、重连与历史插入可能交错** → 最近查询与旧页查询独立管理，使用各自的请求身份和稳定锚点。返回最新时丢弃旧回看的响应。
- **长时间主动回看会累计已加载记录** → 每次最多加载 100 条，只有用户触顶或主动点击才推进。实时增长由最近窗口承接，回到最新后释放回看页。

## Migration Plan

先更新所有可能处理历史请求的后端，再发布向上分页前端。旧前端仍可读取增加字段后的最近页。回退时先切回前端，再回退后端。历史表、主键、已存记录和保留配置可原样使用。
