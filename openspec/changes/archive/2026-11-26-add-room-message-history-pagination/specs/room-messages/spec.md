## MODIFIED Requirements

### Requirement: 房间弹幕面板与恢复

房间页 MUST 提供连接状态、正文输入、发送按钮、发送反馈和独立滚动列表，发送区固定在面板底部。在收到当前房间的 `ready` 后才允许发送。一次主动操作最多发送一次 POST，页面 MUST 禁止重复点击造成再次提交，凭证过期响应、连接恢复和结果不确定只更新当前操作状态。页面 MUST 区分未提交、排队、最终接收、拒绝与结果未确认，按回执更新发送状态，按历史与实时消息更新列表。结果未知时保留提交快照，并在预约已知时提供只读回执查询。用户主动新建提交时生成新标识。

页面 MUST 在 `ready` 后立即合并实时帧。首次就绪、重连就绪、订阅恢复或历史进度高于浏览器已见最大序号时 MUST 查询最近 100 条历史，其中已见序号来自实际收到的消息。每个活跃连接最多有一个最近窗口查询在途，期间收到的多次触发合并为一次后续刷新。成功处理当前快照后结束本轮。最近窗口查询失败时保留已展示内容，并在当前连接内使用有上限的恢复查询。

最近窗口 MUST 按房间序号升序保留最新 100 条，首次显示时定位到底部。最近窗口和回看列表都按 `messageId` 去重，每个序号最多显示一条。迟到项仍在相应展示范围内时插入对应位置。冲突实时帧到达时保留已展示项，读到冲突键对应的持久记录时以其替换本地冲突项。稀疏历史页只合并实际返回的记录，保留范围内未被替换的实时项。有空间时在同一行显示浏览器本地 `HH:mm:ss`、发送者和纯文本正文，空间不足时自然换行。输入法组字期间避免误发送。切换房间或会话、卸载页面时清理列表、提交、历史查询和连接任务，并丢弃旧回调。

用户离开底部时页面 MUST 保留当前阅读范围。向上接近顶部时 MUST 加载更早一页，同时提供键盘可操作的加载入口。第一次向上查询使用回看列表的实际最小序号作为 `beforeSeq`；后续使用历史响应的 `nextBeforeSeq`。每次回看最多允许一个向上请求在途。加载成功后将更早消息合并到列表，保持阅读锚点的位置。页面恢复锚点时不触发下一页。查询失败时保留列表、滚动位置及游标，并提供重试。查询返回空游标后，该次回看 MUST 显示已无更早消息并停止向上请求。

回看期间最新消息 MUST 继续更新最近窗口。超出回看范围的新消息显示「查看新消息」提示，向上翻页不触发该提示。用户通过「查看新消息」或「回到最新」返回最近窗口底部，结束本次回看并释放其历史页。尚未翻页且无待查看消息时，滚回底部也可恢复跟随。同房间同会话的 WebSocket 重连 MUST 保留正在进行的回看和游标。旧房间、旧会话或已退出回看收到的响应不得改变当前页面。

#### Scenario: 广播早于发送响应

- **WHEN** 用户先收到实时消息，再取得 `202` 或正式接收回执
- **THEN** 列表只增加一项，响应和回执只更新该次提交状态

#### Scenario: 发送结果不明确

- **WHEN** 请求超时、响应丢失或回执暂不可见
- **THEN** 页面提示可能已送达并保留该次提交快照。有回执 ID 时可查询，未获取 ID 时可继续查看实时列表或历史。页面和认证封装均不重发原 POST

#### Scenario: 明确的未发送结果或凭证过期

- **WHEN** 发送在入口被熔断拒绝，或发送响应明确表明 Access Token 过期
- **THEN** 页面结束当次发送并保留草稿。凭证续期后也不自动提交原消息，由用户主动发起新的发送操作

#### Scenario: 重连、刷新与换房

- **WHEN** 用户断线重连、刷新页面或切换房间与会话
- **THEN** 同页同会话重连申请新票据并刷新最近历史，保留列表和草稿。刷新页面按首次进房处理，切换时隔离旧回调和旧房间数据

#### Scenario: 消息在阅读和跟随时到达

- **WHEN** 新消息在列表底部跟随或用户上翻阅读时到达
- **THEN** 底部跟随继续，向上阅读时保持仍可见条目的位置并提示「查看新消息」

#### Scenario: 历史与实时交错或漏收末尾事件

- **WHEN** 最近历史还未返回，列表已展示 100 后收到 103，或在订阅中断时漏收窗口内的最后一条弹幕
- **THEN** 103 立即显示，缺号本身不会触发查询。订阅恢复或超过已见最大序号的历史进度触发最近窗口查询，已经落库且仍在窗口内的漏收项可找回

#### Scenario: 迟到、重复和持久记录纠正

- **WHEN** 101 在 103 之后通过实时帧或近期历史到达且仍在窗口内，或者历史返回了与已展示实时项共用一项唯一标识的持久记录
- **THEN** 101 按序插入，重复消息只保留一项。发生冲突时以持久记录纠正对应项，历史响应未包含的其他实时项继续保留

#### Scenario: 合并刷新触发且历史暂不可用

- **WHEN** 已有最近窗口 GET 在途并收到多个恢复提示，后续历史查询暂时不可用
- **THEN** 提示合并为一次后续刷新，期间继续展示实时弹幕。历史恢复查询有次数上限，旧连接的最近查询结果不会写入当前列表

#### Scenario: 发送超限后保留草稿

- **WHEN** 发送接口返回 `429 MESSAGE_RATE_LIMITED` 及 `Retry-After`
- **THEN** 页面保留输入并显示剩余等待时间，倒计时内禁用新发送，已有预约仍可在查询期内读取回执

#### Scenario: 向上分页并保持阅读位置

- **WHEN** 观众先看到最近 100 条，然后向上滚到顶部，或使用顶部加载入口
- **THEN** 页面只发起一次更早页查询，将消息合并到上方，当前可见弹幕保持在原位置，程序调整滚动不会触发下一页

#### Scenario: 实时消息挤出首屏历史

- **WHEN** 首次历史快照读取后，实时消息使页面最早一条的序号大于快照最早序号，随后观众首次向上翻页
- **THEN** 请求使用实际显示的最小序号作为排他边界，已挤出且仍在保留期内的消息可在向上页找回

#### Scenario: 回看时实时到达与重连

- **WHEN** 观众已经翻出更早页，回看范围之外有新弹幕到达，或 WebSocket 断开后重新就绪
- **THEN** 最近窗口独立更新，阅读位置和向上游标保留；有较新弹幕时显示「查看新消息」，点击后回到最新并释放回看页

#### Scenario: 更早页失败、查完和过期响应

- **WHEN** 向上查询暂不可用、已经没有更早记录，或查询期间观众已换房、换会话或退出回看
- **THEN** 暂不可用时保留内容和游标供重试；成功返回空游标时结束本次向上分页；过期响应不会改变当前列表

### Requirement: 历史持久化与有序查询

系统 MUST 将仍在保留期内且无冲突的正式弹幕写入历史，允许房间序号缺口并补写可用的迟到事件。持久进度 MUST 表示每房间曾经成功落库的最大序号，初值为 0，迟到写入或清理不得使其回退。房间、序号、消息 ID、发送者账号与显示名快照、规范化正文和正式受理时间完全一致的重放 MUST 保持原记录。若同 `(roomId, roomSeq)` 或同 `messageId` 对应不同的不可变字段，MUST 保留已有持久记录，当前批次尚未写入时保留分区 offset 更早的有效事件。系统 MUST 跳过本条冲突并记录其位置，继续处理同批其他有效记录。历史保存及进度成功持久化后才可确认消费位置，数据库失败或结果未知时 MUST 保留原消费位置。

系统 MUST 从正式受理时间起保留历史 24 小时，边界到达即过期。查询 MUST 过滤已过期消息，已到期的正常重放不得重新写入。历史的持久分区阻断 MUST 在实例与分区接管间共享。位点越界或需修复的持久分区错误 MUST 同时限制受影响的分区推进、房间历史读取和进度通知。正常交接期间仍提供已提交记录。

系统 MUST 提供经 Bearer 和当前会话鉴权的 `GET /api/v1/rooms/{roomId}/messages`，路径使用规范小写 UUID v4，响应使用 `Cache-Control: no-store`。查询参数 `limit` 缺省为 100，允许 1–100。可选的 `afterSeq` 和 `throughSeq` 为 0–9223372036854775806 的规范十进制字符串，`beforeSeq` 为 1–9223372036854775806 的规范十进制字符串。`beforeSeq` 与其他游标互斥，指定 `throughSeq` 时 MUST 同时指定 `afterSeq`，且上限不得小于游标。未知、重复或无效参数 MUST 返回 `400 INVALID_REQUEST`，不存在的房间返回 `404 ROOM_NOT_FOUND`。

同一页 MUST 从一致快照读取。省略 `beforeSeq` 与 `afterSeq` 时取最近一页。指定 `beforeSeq` 时取 `roomSeq < beforeSeq` 的最近一页。指定 `afterSeq` 时只读 `afterSeq < roomSeq <= 响应 throughSeq`，从序号最小的记录开始。各模式 MUST 按 `roomSeq` 升序返回最多 `limit` 条 `items`，消息字段与实时弹幕一致。响应 MUST 含十进制字符串 `latestStoredSeq` 和 `throughSeq`，后者为请求指定上限与最大落库序号中较小者，未指定时为最大落库序号。范围模式还有较新记录时，`nextAfterSeq` 为本页最大序号；最近模式或向上模式还有更早记录时，`nextBeforeSeq` 为本页最小序号。其余情况相应字段为 `null`。当 `afterSeq` 达到或超过读取上限，或向上边界前无可查询记录时返回空页。后续分页按每次请求时的快照读取，范围补拉可沿用响应上限。历史不可用 MUST 返回 `503 ROOM_MESSAGES_UNAVAILABLE`。缺号、单条冲突和游标位于已清理范围前 MUST 返回当前可读页。

#### Scenario: 首次查询最近历史

- **WHEN** 已登录用户查询存在房间的历史且未传游标
- **THEN** 按房间序号升序返回该房间最近一页，返回本次快照的最大落库序号和相同的读取上限，`nextAfterSeq` 为 `null`，公开字段与实时弹幕一致

#### Scenario: 缺号、范围分页和迟到补写

- **WHEN** 103 已入库但 101 与 102 缺失，用户请求 `afterSeq=100&throughSeq=103`，之后 101 在保留期内到达
- **THEN** 首次返回 103、上限 103 且无下一页。写入 101 后，重新查询最近窗口时按序返回 101 和 103，最大序号仍为 103

#### Scenario: 分页上限与边界

- **WHEN** 范围补拉需要读取多页，或给出的 `afterSeq` 不小于本次实际读取上限
- **THEN** 前者返回本页最后一条实际记录作为下一页游标，沿用返回上限即可继续读取。后者返回 `200` 空页和空游标。非法组合和非规范值返回 `400`

#### Scenario: 历史批次重复消费

- **WHEN** 历史批次已提交，但处理进度未确认，重启后再次收到同一事件
- **THEN** 对应消息仍只有一条且内容保持原值，最大落库序号不回退

#### Scenario: 同分区单条冲突后继续推进

- **WHEN** 同分区内房间 A 的某条事件命中已占用序号或消息 ID 却改变不可变字段，后续仍有 A 与 B 的合法事件
- **THEN** 原历史保持不变，只记录并跳过本条冲突，A 与 B 的有效记录仍入库且两间房仍可查历史

#### Scenario: 数据库异常保留原消费位置

- **WHEN** 批量入库失败、异常不能归因到具体冲突，或事务提交结果不明确
- **THEN** 本批 Kafka 消费位置保持不变，并可从该位置重读

#### Scenario: 历史保留范围已越过客户端游标

- **WHEN** 游标在部分已清理序号之前，且历史组再次读到已到期的消息
- **THEN** 接口返回仍在保留期内的可读记录或空页，正常重放不会重新创建已到期记录，最大落库序号仍保留

#### Scenario: 历史阻断在分区迁移后仍生效

- **WHEN** 历史分区的已提交位点超出可读范围或该分区出现须修复的持久处理错误，随后由另一实例接管
- **THEN** 向任意接入实例读取受影响分区的历史均返回 `503 ROOM_MESSAGES_UNAVAILABLE`，相应历史进度通知暂停，其他分区继续读取和推进

#### Scenario: 最近一页后向上翻页

- **WHEN** 同一房间仍保留序号 1 到 200 的记录，调用者先查最近页，再提交 `beforeSeq=101&limit=100`
- **THEN** 最近页返回 101 到 200 和 `nextBeforeSeq: "101"`；向上页返回 1 到 100 和 `nextBeforeSeq: null`；两页均升序返回，`nextAfterSeq` 均为 `null`

#### Scenario: 向上游标跨越缺号和过期行

- **WHEN** 调用者传入的 `beforeSeq` 对应行已过期或不存在，边界前的序号也有缺口
- **THEN** 接口以排他序号比较取最近的可读记录，超过一页时使用本页最小序号推进；边界前无可读记录时返回空页及两个空游标

#### Scenario: 无效向上游标

- **WHEN** 调用者指定 `beforeSeq=0`、不规范十进制字符串、越界值、重复参数，或与 `afterSeq` 或 `throughSeq` 组合使用
- **THEN** 返回 `400 INVALID_REQUEST`
