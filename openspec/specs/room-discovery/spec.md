# room-discovery Specification

## Purpose

为 LiveFlow 已登录用户提供统一的直播间目录。用户可以按创建时间浏览所有已创建的房间，按名称查找目标，通过分页继续浏览，并直接打开自己或其他用户的房间。

## Requirements

### Requirement: 已创建直播间目录

系统 MUST 提供 `GET /api/v1/rooms`，要求有效 Bearer 和当前会话。成功 MUST 返回 `200`、`Cache-Control: no-store` 和 JSON `{items, nextCursor}`。每项 MUST 包含 `roomId`、`title`、`ownerName`、`createdAt`、`isMine`。`roomId` 为房间标准小写 UUID v4，`createdAt` 为带三位小数秒的 UTC ISO 8601 字符串，`isMine` 由认证账号与房主归属比较得到。房主有昵称时 MUST 使用昵称，无资料或昵称为空时 MUST 使用保留原拼写的登录用户名。所有已创建房间均可读取，包括本人房间。响应 MUST 隐藏内部账号 ID。

#### Scenario: 读取本人和其他账号的房间

- **WHEN** 有效登录用户读取列表，数据库中同时存在本人和其他账号的房间
- **THEN** 两类房间按同一顺序返回，仅本人房间的 `isMine` 为 `true`，有昵称和无昵称的房主分别返回昵称和原拼写用户名

#### Scenario: 鉴权和存储故障

- **WHEN** 列表请求的凭证无效，或有效会话查询时房间存储暂不可用
- **THEN** 凭证无效按认证契约拒绝，房间读取故障返回 `503 ROOM_SERVICE_UNAVAILABLE`

### Requirement: 按房间名称搜索

`GET /api/v1/rooms` MUST 支持可选字符串 `q`，复用房间名称的原始字符检查和 Unicode 首尾空白清理规则，清理后允许 0–40 个 Unicode 码点。省略或规范化后为空时浏览全部房间。非空关键词 MUST 匹配标题中的连续文字，保留内部空白，英文忽略大小写；`%`、`_`、`!` 均按普通字符匹配。未知、重复或无效的查询参数 MUST 返回 `400 INVALID_REQUEST`。

#### Scenario: 完整列表和包含匹配

- **WHEN** 用户提交空关键词、一个汉字，或包含大小写英文和字面 `%_!` 的合法关键词
- **THEN** 空关键词浏览全部，非空关键词只返回名称匹配的房间，并使用与完整列表相同的顺序

#### Scenario: 拒绝无效查询参数

- **WHEN** 用户提交重复或未知的查询参数，或关键词超过限制或含禁止字符
- **THEN** 系统返回 `400 INVALID_REQUEST`

### Requirement: 房间列表稳定翻页

浏览和搜索 MUST 统一按 `createdAt` 倒序排列，同一毫秒按 `roomId` 倒序排列。可选参数 `limit` 默认为 12，允许 1–24 的整数。首屏省略 `cursor`，后续页使用相同规范化关键词对应的 `nextCursor`。下一页 MUST 从上一页最后一条记录之后读取。无下一页时 `nextCursor` MUST 为 `null`，无结果时 `items` MUST 为 `[]`。无效页大小、空或无效游标、关键词与游标不匹配 MUST 返回 `400 INVALID_REQUEST`。

#### Scenario: 同一毫秒的房间跨页

- **WHEN** 多个房间的创建时间相同，用户在同一关键词下依次读取各页
- **THEN** 房间以 UUID 倒序跨页连续返回，已有记录无重复、无遗漏，最后一页返回空游标

#### Scenario: 在翻页期间创建更新的房间

- **WHEN** 已读取第一页后出现一个排序在游标之前的新房间
- **THEN** 继续翻页从原边界之后读取，重新查询第一页时可见该新房间

#### Scenario: 用旧关键词的游标查新关键词

- **WHEN** 用户将一个有效游标带入不同的规范化关键词查询
- **THEN** 系统返回 `400 INVALID_REQUEST`，可以省略游标从新条件的首页重新查询

### Requirement: 目录作为默认登录页

Vue MUST 在有效会话打开 `/` 时展示统一目录。普通登录成功后进入该目录，从受保护地址登录后继续该地址。目录顶部 MUST 提供按名称搜索和个人主页入口，每行显示房间名称、房主显示名、本地创建时间和进入操作；本人房间显示「我的房间」。进入房间 MUST 使用 `/rooms/{roomId}`。

#### Scenario: 搜索、刷新和切换搜索

- **WHEN** 用户按 Enter 或点击搜索，随后刷新、前进、后退、清空搜索或提交另一关键词
- **THEN** URL 的 `q` 反映已提交条件，页面按对应条件从第一页读取，旧请求或旧会话的结果无法追加到当前列表

#### Scenario: 列表为空、搜索无结果与读取失败

- **WHEN** 系统没有已创建房间、搜索无结果，或首页或后续页读取失败
- **THEN** 页面分别提供创建入口、清空搜索或重试；后续页失败保留已展示的结果，游标被拒绝时按当前关键词重新查首页

#### Scenario: 从搜索结果进入和返回

- **WHEN** 用户在搜索结果打开任意房间，然后点击「返回直播间列表」
- **THEN** 房间展示对应详情，返回时恢复已提交关键词并从该条件的第一页读取
