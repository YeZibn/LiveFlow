# room-creation Specification

## Purpose

让 LiveFlow 的已登录用户在个人主页创建和查询自己的直播间，确保归属稳定、每账号最多一间，并在刷新、并发操作或请求结果不明确时恢复正确的房间展示。

## Requirements

### Requirement: 登录用户创建本人房间

系统 MUST 提供 `POST /api/v1/rooms`，要求有效 Bearer 会话和 CSRF，按认证账号创建房间。请求 MUST 为只含字符串 `title` 的 JSON 对象。名称先拒绝 C0、C1 控制字符及 Unicode 行段分隔符，再按 Unicode White_Space 去除首尾空白，结果 MUST 为 1–40 个 Unicode 码点，保留内部空白与大小写。提交成功 MUST 返回 `201`、`Cache-Control: no-store` 以及房间对象，其中 `roomId` 为标准小写随机 UUID v4，保存后保持稳定，`createdAt` 为带三位小数秒的 UTC ISO 8601 字符串，`title` 为规范化后的名称。

启用共享房间存在性缓存后，系统 MUST 在房间事务确认提交后更新该 UUID 的可见结果。成功更新后，先于该事务确认的不存在结果 MUST 无法重新覆盖已存在结果。缓存更新失败时 MUST 继续以已提交的房间返回 `201`，旧的不存在结果 MUST 在创建提交后不超过配置的负缓存 TTL 上限内失效。事务回滚或提交结果未确认时，创建路径 MUST 保持缓存中无该事务产生的存在结果。

#### Scenario: 创建成功

- **WHEN** 当前账号没有房间，用户携带有效会话及 CSRF 提交合法名称
- **THEN** 系统返回 `201` 和已创建的房间，后续本人查询返回相同房间

#### Scenario: 拒绝无效创建请求

- **WHEN** 请求缺少必填字段、包含额外字段、字段类型错误、JSON 无效或名称不符合规则
- **THEN** 接口返回 `400 INVALID_REQUEST`，且请求没有创建房间

#### Scenario: 拒绝无效凭证

- **WHEN** 写请求的 Bearer 或当前会话无效，或认证用户的请求未通过 CSRF
- **THEN** 系统按现有契约返回对应的认证或 CSRF 错误，且请求没有创建房间

#### Scenario: 创建后旧的不存在结果晚到

- **WHEN** 一个实例已确认房间不存在、尚未发布结果，另一个实例提交该 UUID 对应的房间并成功更新缓存
- **THEN** 后续查房以存在为准，晚到的不存在结果无法使该房间重新不可见

#### Scenario: 创建已提交但缓存不可用

- **WHEN** 房间写入已经提交，但无法写入共享缓存
- **THEN** 创建仍返回 `201` 和已持久化的 UUID，本人查询或详情可取得该房间，旧的不存在结果在负缓存 TTL 上限内失效

#### Scenario: 创建回滚或提交未知

- **WHEN** 创建事务回滚或提交结果无法确认
- **THEN** 创建路径不会提前发布存在结果，后续查询按已提交数据确认实际结果

### Requirement: 一人一房与本人查询

系统 MUST 保证每账号最多一个房间。名称允许重复。重复创建 MUST 返回 `409 ROOM_ALREADY_EXISTS` 并保留原房间。系统 MUST 提供 `GET /api/v1/users/me/room`，仅查询当前有效会话对应账号的房间，返回不可缓存的 `200` 和 `room` 字段。房间存在时，`room.roomId` MUST 为该房间的标准小写 UUID v4。房间存储不可用时 MUST 返回 `503 ROOM_SERVICE_UNAVAILABLE`，账号不存在时 MUST 按会话失效处理。

#### Scenario: 同账号并发创建

- **WHEN** 同一个尚无房间的账号用有效凭证并发提交两次合法创建
- **THEN** 正常存储条件下一个请求返回 `201`，另一个返回 `409 ROOM_ALREADY_EXISTS`，本人查询只返回获胜请求的房间且名称未被覆盖

#### Scenario: 不同账号同名与归属隔离

- **WHEN** 两个没有房间的账号分别提交相同名称并各自查询
- **THEN** 各自获得不同的房间标识，并仅查询到自己的房间

#### Scenario: 尚未创建及读取故障

- **WHEN** 当前账号没有房间，或者系统无法读取房间
- **THEN** 前者返回 `200` 和 `{"room": null}`，后者返回 `503 ROOM_SERVICE_UNAVAILABLE`

### Requirement: 个人主页房间操作与恢复

Vue MUST 在 `/profile` 的个人主页独立显示「我的直播间」，区分加载、空结果、已有房间和读取失败。空结果时提供仅含房间名称的创建表单，提交期间禁止重复操作，成功时显示返回的名称，页面隐藏用户 ID。房间存在时 MUST 提供指向 `/rooms/{roomId}` 的「进入直播间」入口。切换会话后，旧请求的结果 MUST 无法更新当前页面。

#### Scenario: 成功后刷新或重新登录

- **WHEN** 用户创建成功并刷新个人主页，或重新登录后再次进入个人主页
- **THEN** 页面重新从本人查询结果展示已创建的房间，返回列表时可在重新加载的目录中浏览该房间

#### Scenario: 并发或未知结果后恢复

- **WHEN** 创建返回房间已存在，或提交超时、响应丢失而无法确认结果
- **THEN** 页面保留输入并先查询本人房间，查到时展示房间，明确查空时允许手动重试，查询失败时提供重新读取入口

#### Scenario: 读取与资料状态独立

- **WHEN** 进入个人主页后房间读取失败但个人资料加载成功
- **THEN** 页面展示个人资料，房间区显示读取失败与重试入口

### Requirement: 房间 UUID 与详情查询

系统 MUST 为迁移前已存在的房间补齐唯一的随机 UUID v4，并保留房主、名称和创建时间。系统 MUST 提供 `GET /api/v1/rooms/{roomId}`，仅接受有效登录会话和标准小写 UUID v4。成功 MUST 返回 `200`、`Cache-Control: no-store` 和仅含 `roomId`、`title`、`ownerName` 的 JSON。`ownerName` MUST 取当前房主昵称，空昵称或无资料时取原拼写用户名。详情读取无写入副作用。

#### Scenario: 查询已迁移的房间

- **WHEN** 迁移前存在的房间完成迁移，用户从本人查询取得 UUID 并打开详情
- **THEN** 三次读取所得标识保持一致，包括迁移后首次本人查询、详情和再次本人查询，原房主、名称及创建时间保持原值

#### Scenario: 另一账号通过链接查询房间

- **WHEN** 有效登录的其他账号请求存在房间的标准 UUID
- **THEN** 详情返回 `200`、房间 UUID、名称和房主显示名，后续本人查询仍只返回该访问者自己的房间

#### Scenario: 无效路径参数与房间缺失

- **WHEN** 有效登录用户使用无效 UUID 格式，或提交一个合法但不存在的 UUID
- **THEN** 前者返回 `400 INVALID_REQUEST`，后者返回 `404 ROOM_NOT_FOUND`

#### Scenario: 鉴权与详情读取故障

- **WHEN** 详情请求缺少有效会话，或有效会话的请求遇到房间存储故障
- **THEN** 前者按现有认证契约拒绝，后者返回 `503 ROOM_SERVICE_UNAVAILABLE`

### Requirement: 进入直播间页面与分享

Vue MUST 支持从统一列表、本人房间及分享链接打开并刷新 `/rooms/{roomId}`。未登录时 MUST 保留路径和查询参数，登录成功后继续加载该房间。详情成功后页面 MUST 以深色布局展示标题、房主显示名、返回直播间列表、复制链接、16:9 直播画面占位区和独立弹幕面板。桌面端左侧为观看区、右侧为弹幕，移动端上下排列。页面隐藏用户 ID。只有属于当前路由和当前会话的响应才可更新页面。

#### Scenario: 从个人主页进入并分享

- **WHEN** 房主点击「进入直播间」并复制链接
- **THEN** 页面显示对应房间，复制内容使用该房间 UUID 并反馈结果，其他有效登录用户可打开该链接，返回列表时进入 `/`

#### Scenario: 从分享链接登录并刷新

- **WHEN** 未登录用户通过房间链接进入，完成登录后刷新
- **THEN** 登录和刷新均在原地址继续，恢复会话后展示该房间；直接打开的分享房间返回目录时进入 `/`

#### Scenario: 房间页失败与重试

- **WHEN** 房间链接无效、房间不存在或详情读取暂时失败
- **THEN** 页面展示对应提示。前两种情况提供返回直播间列表入口，暂时失败保留房间地址并支持重试

#### Scenario: 路由或会话切换

- **WHEN** 旧请求发出后切换房间或登录会话，旧响应晚于切换返回
- **THEN** 当前页面只展示当前路由与会话对应的房间信息

#### Scenario: 弹幕连接故障时保留房间操作

- **WHEN** 房间详情已成功加载，但弹幕连接建立失败或断开
- **THEN** 弹幕面板展示连接状态及适用的恢复入口，房间标题、复制链接与返回直播间列表仍可用
