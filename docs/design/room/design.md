# 直播间 V1 设计

## 背景、目标与范围

已登录用户可以在个人主页创建自己的直播间，并在刷新页面或重新登录后看到已创建的房间。本版确定一人一房，创建表单只填写房间名称。房间名称可以重复，不同账号各自管理自己的房间。 [个人主页设计](../profile/design.md)

本版覆盖创建房间、查询本人房间，以及通过链接进入直播间页面。房主从个人主页进入，其他已登录用户可打开同一个链接。公开列表、开播与关播、房间编辑与删除归入后续阶段。右侧弹幕列表和实时接入由弹幕模块定义。 [直播间弹幕设计](../room-messages/design.md)

## 方案选择与设计思路

- **房间独立于个人资料。** 房间通过稳定的账号 ID 归属 `users`。用户即使尚未保存个人资料，也可以创建房间。修改昵称、头像或简介后，房主关系保持有效。
- **按访问场景读取房间。** 本人查询用于个人主页展示和确认创建结果，详情查询用于打开链接和刷新房间页。
- **对外使用随机 UUID v4。** 房间创建后对外标识保持稳定，供 API、页面路由和分享链接共用。数据库内部主键继续用于表关联。 [存储与迁移规则](database.md)
- **进入权限由登录会话决定。** 任何有效登录会话都可用房间 UUID 读取详情。打开房间页是只读操作，重复打开、刷新和多标签页访问共用同一查询。
- **一人一房由数据库约束。** 同一账号的多个请求可能从不同标签页或实例同时到达。数据库在插入时裁决，只允许一条记录提交，后续创建请求返回冲突。 [表约束与写入规则](database.md#读写与事务)
- **房间创建与开播分开。** 首版用房间记录表示已创建，无需直播状态字段。创建过程只写 MySQL，Redis 继续负责校验认证会话。

## 模块分工与依赖

| 参与方 | 职责 |
| --- | --- |
| Vue 个人主页 | 「我的直播间」处理查询、创建与结果确认，以响应中的 UUID 生成进入链接。 |
| Vue 直播间页 | 从 URL 取得 UUID，复用 `withAccess` 加载详情，管理路由和会话切换后的页面状态。 |
| `liveflow-api` | 通过 Spring MVC 提供房间 Controller、请求与响应类型及错误映射。安全过滤链校验当前会话和适用的 CSRF，Controller 从可信 JWT 取得账号 ID。 |
| `liveflow-core` | 房间 Service 管理名称校验、UUID 生成、查询和创建。Mapper 提供按房主和按 UUID 查询。Flyway 管理增列、回填和约束。 |
| MySQL | `users` 提供账号归属，`rooms` 保存房间。房主及 UUID 唯一索引分别保证一人一房和标识唯一。 |
| `liveflow-infrastructure` | 沿用现有 Redis 会话存储支持认证。 |

实现时为跨层方法和前端请求入口补充职责、参数、返回值及适用的异常说明。关键语句的注释说明房主身份来源、两种唯一约束冲突的处理、创建结果回读，以及登录后如何继续打开原房间。

## 端到端流程

### 创建和查询本人房间

1. 用户登录或恢复会话后进入个人主页。房间区独立读取本人房间。读到空结果时显示「创建直播间」，读到房间时显示名称。读取失败时显示「重新读取」，个人资料区可独立展示。
2. 用户点击「创建直播间」原地展开单字段表单。提交期间禁用提交按钮。后端校验请求、名称和账号归属，再创建房间。 [名称规则](api.md#创建房间)
3. 事务提交后，接口返回 UUID 和服务端规范化的房间名称。页面收起表单，展示该名称和「进入直播间」。
4. 刷新或重新登录后，页面重新读取当前账号的房间。退出或切换会话时随旧页面卸载清理表单和展示状态，迟到响应只作用于发起请求的会话。

### 通过房间链接进入

1. 用户从个人主页或分享链接打开 `/rooms/{roomId}`。直接访问和刷新均由服务器返回 Vue 应用入口，`/api/` 请求交给后端。
2. 前端先恢复会话。需要登录时，在当前地址显示登录表单，登录成功后继续加载该地址的房间。
3. 前端经 `withAccess` 读取详情。后端校验会话后按 UUID 查询。进入成功后展示房间名称。 [房间详情接口](api.md#查询房间详情)
4. 房间切换或会话变更时清理旧页面状态，只接受与当前房间 UUID 和会话匹配的响应。过期请求即使成功也不更新当前页面。

## 房间页面框架

顶部展示房间名称、「返回个人主页」和「复制链接」。链接使用当前站点地址和房间 UUID，复制操作给出成功或失败反馈。页面沿用现有暖白与深绿色样式，继续隐藏用户 ID。

桌面端左侧为深色 16:9 直播画面区，右侧为独立弹幕面板。手机端改为画面在上、弹幕在下。画面区显示「直播画面尚未接入」，已有房间页的弹幕区显示「弹幕暂未开放」。弹幕 V1 接入后，该区域承载连接状态、消息列表和发送表单。播放控制和在线人数随对应能力接入。 [弹幕页面流程](../room-messages/design.md#端到端流程)

## 失败、并发与恢复

| 场景 | 行为 |
| --- | --- |
| 名称或请求无效 | 保留表单并提示修改。当前请求无写入。 |
| 当前会话已失效或 CSRF 校验失败 | 沿用认证错误处理。只有明确的 Access Token 过期错误可经同会话续期后重发一次原请求。CSRF 校验失败时保留表单，重新获取 CSRF 后由用户再次提交。 |
| 已有房间或多个标签页同时创建 | 已有房间继续生效，重复创建返回冲突。页面重新读取并展示存在的房间。 |
| 创建超时、响应丢失或房间存储故障 | 保留输入并重新读取。查到房间就显示该结果。查到空结果后允许手动重试。确认读取本身失败时继续提供「重新读取」。 |
| 房间链接格式无效或房间不存在 | 显示相应提示，并提供返回个人主页入口。 |
| 房间详情读取失败 | 保留当前房间地址，提供重新读取入口。 |
