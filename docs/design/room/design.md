# 直播间 V1 设计

## 背景、目标与范围

已登录用户可以在个人主页创建自己的直播间，并在刷新页面或重新登录后看到已创建的房间。本版确定一人一房，创建表单只填写房间名称。房间名称可以重复，不同账号各自管理自己的房间。 [个人主页设计](../profile/design.md)

现有实现支持创建房间、查询本人房间，以及通过 UUID 链接进入。本轮增加登录后的统一直播间列表，用户可以按创建时间浏览、按名称搜索，并直接进入任意已创建的房间。房间内同步更新观看布局与弹幕展示。开播与关播、房间编辑与删除归入后续阶段。 [直播间弹幕设计](../room-messages/design.md)

## 方案选择与设计思路

- **房间独立于个人资料。** 房间通过稳定的账号 ID 归属 `users`。用户即使尚未保存个人资料，也可以创建房间。修改昵称、头像或简介后，房主关系保持有效。
- **所有已创建房间使用同一个目录。** 登录后的默认页为 `/`，自己的房间与其他房间一起按创建时间从新到旧排列。个人主页 `/profile` 保留资料设置和「我的直播间」，本人查询也用于确认创建结果。
- **搜索只匹配房间名称。** 输入标题的一段连续文字即可找到房间。浏览和搜索使用同一种排序，创建时间相同时按 UUID 倒序排列，以相同顺序继续翻页。 [搜索接口](api.md#浏览与搜索直播间)
- **对外使用随机 UUID v4。** 房间创建后对外标识保持稳定，供 API、页面路由和分享链接共用。数据库内部主键继续用于表关联。 [存储与迁移规则](database.md)
- **进入权限由登录会话决定。** 任何有效登录会话都可用房间 UUID 读取详情。打开房间页是只读操作，重复打开、刷新和多标签页访问共用同一查询。
- **一人一房由数据库约束。** 同一账号的多个请求可能从不同标签页或实例同时到达。数据库在插入时裁决，只允许一条记录提交，后续创建请求返回冲突。 [表约束与写入规则](database.md#读写与事务)
- **房间创建与开播分开。** 首版用房间记录表示已创建，无需直播状态字段。MySQL 事务确定创建结果，房间存在性缓存可在事务提交后预热。

## 模块分工与依赖

| 参与方 | 职责 |
| --- | --- |
| Vue 直播间列表 | 管理关键词、列表状态和游标分页，以响应中的 UUID 生成进入链接。 |
| Vue 个人主页 | 「我的直播间」处理查询、创建与结果确认，以响应中的 UUID 生成进入链接。 |
| Vue 直播间页 | 从 URL 取得 UUID，复用 `withAccess` 加载详情，管理路由和会话切换后的页面状态。 |
| `liveflow-api` | 通过 Spring MVC 提供房间 Controller、请求与响应类型及错误映射。安全过滤链校验当前会话和适用的 CSRF，Controller 从可信 JWT 取得账号 ID。 |
| `liveflow-core` | 房间 Service 管理名称校验、UUID 生成、创建和查询，负责搜索参数、游标和房间存在性判定。Mapper 按场景查询房间及显示名，Flyway 管理表结构与索引。 |
| MySQL | `rooms` 保存房间，`users` 和 `user_profiles` 提供房主显示名。列表查询使用创建时间与 UUID 组合索引。 |
| `liveflow-infrastructure` | 现有 Redis 会话存储支持认证。房间缓存接入独立 Redis，使用 Lua 协调跨实例回填和创建后预热。 |

实现时为跨层方法和前端请求入口补充职责、参数、返回值及适用的异常说明。关键语句的注释说明房主身份来源、两种唯一约束冲突的处理、创建结果回读，以及登录后如何继续打开原房间。

## 端到端流程

### 创建和查询本人房间

1. 用户从直播间列表顶部进入 `/profile`。房间区独立读取本人房间。读到空结果时显示「创建直播间」，读到房间时显示名称。读取失败时显示「重新读取」，个人资料区可独立展示。
2. 用户点击「创建直播间」原地展开单字段表单。提交期间禁用提交按钮。后端校验请求、名称和账号归属，再创建房间。 [名称规则](api.md#创建房间)
3. 事务提交后，服务端可预热房间存在性缓存，并返回 UUID 和规范化的房间名称。页面收起表单，展示该名称和「进入直播间」。 [缓存预热](storage.md#创建预热和可见性)
4. 刷新个人主页或下次进入时，页面重新读取本人房间。返回直播间列表重新读取首页，可以看到已创建的房间。退出或切换会话时清理旧会话的表单和展示状态。

### 浏览与搜索直播间

1. 普通登录成功后进入 `/`。顶部提供搜索框、搜索按钮和个人主页入口。列表每行展示房间名称、房主显示名、按浏览器本地时区格式化的创建时间，以及「进入直播间」按钮。本人的房间加上「我的房间」标记，参与同一排序。
2. 用户按 Enter 或点击搜索后，将提交的规范化关键词同步到 URL 的 `q`，清除旧结果和游标并加载新首页。清空搜索时移除 `q` 并恢复全量列表。刷新或浏览器前进、后退时按地址中的 `q` 重新加载。
3. 有下一页时显示「加载更多」。一次只发一个翻页请求，成功后按服务端顺序追加结果。切换查询、离开页面或换会话时取消在途请求或忽略迟到响应。
4. 全量列表为空时显示「暂无直播间」，并提供前往个人主页创建的入口。搜索为空时显示「未找到匹配的直播间」，并提供清空搜索的操作。

### 通过房间链接进入

1. 用户从直播间列表、个人主页的「我的直播间」或分享链接打开 `/rooms/{roomId}`。直接访问和刷新均由服务器返回 Vue 应用入口，`/api/` 请求交给后端。
2. 前端先恢复会话。需要登录时保留原路径和查询参数，登录成功后继续加载该地址。
3. 前端经 `withAccess` 读取详情，展示房间名称和房主显示名，再按弹幕协议申请 Ticket 建立接收连接。访问房间只读取详情和建立临时连接，无需保存成员关系或增加加入接口。 [房间详情接口](api.md#查询房间详情) · [弹幕连接流程](../room-messages/design.md#申请票据并加入房间)
4. 房间切换或会话变更时清理旧页面状态，只接受与当前房间 UUID 和会话匹配的响应。过期请求即使成功也不更新当前页面。

## 房间页面框架

顶部工具栏提供「返回直播间列表」与「复制链接」。从列表进入时，返回操作恢复上次已提交的关键词。从分享链接或个人主页进入时，返回 `/`。复制内容为当前站点下的房间地址，操作后给出反馈。标题区域展示房间名称和房主显示名。

房间采用深灰背景与分层面板，品牌绿色用于主要操作和可用状态。桌面端左侧为 16:9 观看区，右侧为 320–380 px 的弹幕面板。窄屏以观看区在上、弹幕面板在下布局。观看区继续显示「直播画面尚未接入」。弹幕面板由连接状态、独立滚动的消息列表和底部发送区组成。 [弹幕展示规则](../room-messages/design.md#弹幕面板)

## 房间存在性缓存

现有 Ticket 签发、WebSocket 兑票、弹幕发送和历史查询各自通过 `RoomService.exists()` 直接查 MySQL。同机三实例基线里，300 次热门房间 Ticket 请求对应 300 条存在性 SQL。热门历史请求还要读取阻断、水位和消息页。 [基线与对照场景](storage.md#基线与对照场景)

本轮为上述入口增加独立 Redis 缓存。鉴权与 UUID 校验仍在前，缓存只提供该房间是否存在。房间详情和目录继续通过 MySQL 取得名称和当前房主显示名。 [房间详情契约](api.md#查询房间详情) · [弹幕调用契约](../room-messages/v2/api.md#房间存在性判定)

同一个房间未命中时，三台实例用共享回填租约合并查库。MySQL 明确查无房间时回填短期负缓存。不同 UUID、缓存冷启动或缓存故障时，实例仅在本机预算内回源。预算不足或依赖无法确认时返回暂不可用。创建事务提交后预热正缓存，并阻止之前的回填覆盖创建结果。 [缓存读写与降级](storage.md) · [发布与运行](deployment-and-operations.md)

## 失败、并发与恢复

| 场景 | 行为 |
| --- | --- |
| 名称或请求无效 | 保留表单并提示修改。当前请求无写入。 |
| 当前会话已失效或 CSRF 校验失败 | 沿用认证错误处理。只有明确的 Access Token 过期错误可经同会话续期后重发一次原请求。CSRF 校验失败时保留表单，重新获取 CSRF 后由用户再次提交。 |
| 已有房间或多个标签页同时创建 | 已有房间继续生效，重复创建返回冲突。页面重新读取并展示存在的房间。 |
| 创建超时、响应丢失或房间存储故障 | 保留输入并重新读取。查到房间就显示该结果。查到空结果后允许手动重试。确认读取本身失败时继续提供「重新读取」。 |
| 列表首页加载失败 | 保留关键词，显示错误和「重试」，重试从首页开始。 |
| 加载更多失败 | 保留已经展示的房间和当前游标，允许重试该页。游标被拒绝时从同一关键词的首页重新查询。 |
| 房间链接格式无效或房间不存在 | 显示相应提示，并提供返回直播间列表入口。 |
| 房间详情读取失败 | 保留当前房间地址，提供重新读取入口。 |
| 弹幕链路暂时无法确认房间存在 | 返回弹幕服务暂不可用，发送在预约前结束。 [弹幕错误契约](../room-messages/v2/api.md#房间存在性判定) |

发布时先完成列表索引迁移，并将提供列表、房主显示名和弹幕发送者显示名的后端切入流量，再上线新版 Vue。回退时先恢复旧版 Vue，再视需要回退后端。
