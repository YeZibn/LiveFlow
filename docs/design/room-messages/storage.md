# 直播间弹幕存储与状态

## 数据归属

MySQL 的 `rooms` 提供房间是否存在和稳定的房间 UUID。Redis 维持登录会话权威状态，并暂存待消费的连接 Ticket。连接、账号额度、去重记录及待发送队列由当前 JVM 持有。首版没有弹幕持久化数据和数据库迁移。 [弹幕设计](design.md) · [房间数据库设计](../room/database.md) · [认证会话设计](../auth/session.md)

## Redis Ticket

| 内容 | 约定 |
| --- | --- |
| 票据值 | 服务端用 32 字节安全随机数生成，使用无填充 Base64URL 编码。 |
| Key | `liveflow:rooms:ws-ticket:{digest}`，其中 `digest` 是票据字符串的 SHA-256 十六进制摘要。 |
| Value | JSON 对象，包含账号 ID、登录会话 UUID 和房间 UUID。 |
| 生命周期 | 写入时设置 **30 秒 TTL**，签发成功后返回原始票据。仅在票据兑换时读取，经一次原子读取与删除完成消费。 |

写入使用 Redis `SET` 的 `NX` 和 `EX` 选项，一次完成占位和设置过期时间。键冲突时重新生成。消费使用 Redis `GETDEL`。两个并发兑换最多一个取得绑定信息。消费后复查票据绑定的当前会话，失败时连接退出，票据保持已消费。Redis 读取或写入无法确认时不得确认鉴权成功。客户端下一次连接重新申请票据。 [Redis GETDEL](https://redis.io/docs/latest/commands/getdel/)

## JVM 状态与生命周期

| 状态 | 键及内容 | 保留与清理 |
| --- | --- | --- |
| 接收连接 | `roomId → 连接集合`，连接保存房间、账号、登录会话、发送队列及连接状态。 | 仅就绪连接参与广播。关闭、退出和校验失败时注销，房间最后一条连接离开后释放空集合。 |
| 账号额度 | 按账号 ID 保留已接受提交的时间。 | 滚动 **10 秒**窗口内最多 **5 条**，过期记录清理后可接受新提交。标签页与房间共享额度。 |
| 已接受提交 | `会话 ID + 房间 UUID + clientMessageId → 规范化正文、messageId、sentAt`。 | 从首次接受起保留 **60 秒**。重试不延长保留时间。进程退出时释放。 |
| 接收队列 | 每条连接独立的有界先进先出队列。 | 连接关闭时释放，达到容量或持续写入超时时关闭该连接。 |

默认每连接保留 **64 条待发送消息**，单次写入超时为 **5 秒**。本实例最多持有 **512 条连接**，其中最多 **64 条待鉴权连接**，并保留最多 **4096 个已接受提交**。这些参数都可按部署资源配置。达到去重容量时拒绝新提交，并保留尚在去重窗口内的记录。过载只影响达到限制的连接或尚未被接受的新请求。

## 提交裁决与广播顺序

1. 完成 HTTP 鉴权、房间读取和输入校验后，在该账号的串行裁决范围内先查去重记录。相同规范化正文返回原接受结果，正文不同返回冲突。两者都不占用发送额度。
2. 新提交检查账号滑动窗口和接收容量。通过后进入房间分发顺序，生成唯一消息 ID 与时间，向当时的就绪连接队列入队。房间内不同账号的并发以实际分发顺序为准。
3. 记录已接受结果并消耗一次额度，随后返回 HTTP 成功。在同一请求的判重与接受之间，其他标签页不能再次接受相同提交。可按账号、房间的固定顺序进入内存临界区，避免两个裁决路径互相等待。
4. 房间分发只做有界入队，网络写入在临界区外由每条连接串行完成。单连接队列满时从房间移除该连接，并在临界区外关闭。其他连接照常入队，已接受的消息仍返回成功。

接收队列管理与入房使用同一房间顺序。连接在入房前入队 `ready`，退出后不进入后续广播。HTTP 成功确认本机受理，不承诺特定连接收到。任何网络或进程故障都可能让接收方错过消息。

## 会话复查与资源释放

- 待鉴权连接的首帧期限为 **5 秒**。超时、断开或任何鉴权失败都释放待鉴权占用。
- 就绪连接每 **20 秒**通过协议级 Ping 检查存活，等待 Pong 的期限为 **10 秒**。原登录会话默认每 **15 秒**复查一次。复查发现被替换、撤销、过期或无法确认时，立即注销并关闭连接。复查依据 Redis 当前会话，票据过期时间不再参与判断。
- 注销对重复关闭、失败回调和超时清理是幂等操作。每条连接的待发送队列和定时任务一并释放。清理周期同时清除过期账号计数和去重记录。
- 应用重启后，客户端用新 Ticket 重连。旧接收队列和去重记录无法恢复，页面只接收此后的实时消息。
