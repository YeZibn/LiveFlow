# 直播间弹幕 V1 设计

## 背景、目标与范围

房间页支持单实例内的纯文本弹幕。列表同一行展示本地秒级时间、发送者显示名和正文，空间不足时自然换行。同房间已建立接收连接的用户，包括发送者，可以看到广播。 [直播间设计](../room/design.md) · [消息组件](../../../frontend/src/room/RoomMessages.vue)

首版使用页面内的实时列表。画面滚动弹幕、断线补发、历史查询、在线人数和跨实例广播归入后续阶段。

## 方案选择与设计思路

- **HTTP 提交，WebSocket 接收。** 发送复用 MVC、Bearer、CSRF 和 Redis 当前会话校验。HTTP 成功表示服务端已接受一次提交。弹幕列表通过 WebSocket 消息更新，每次提交只展示一次。
- **发送者名称随消息确定。** 后端从已认证账号读取发送者当前显示名，有昵称时使用昵称，否则使用原拼写的登录用户名。广播一次确定后，每位接收者看到同一个名称。昵称修改对之后读取资料的新提交生效。 [显示名规则](../profile/api.md#成功响应) · [接收帧字段](api.md#websocket-接收协议)
- **Ticket 负责建立房间连接。** 已登录用户申请绑定账号、登录会话和房间的一次性短期票据，连接在第一条应用消息中提交票据。连接建立后由当前登录会话决定是否继续接收。
- **按房间顺序分发，按连接独立写入。** 服务端为同房间的提交确定接受顺序，按该顺序向已就绪连接入队。每条连接串行写网络，慢连接达到限制后退出，其他连接继续收发。
- **短期记录用于恢复不确定结果。** 用户可以在原实例仍保有已接受记录时，使用相同请求标识和正文查询式重试，取得原消息 ID 和时间。这个保证覆盖当前实例的短期内存记录，实例重启后记录随之消失。 [状态与一致性](storage.md#提交裁决与广播顺序)

## 模块分工与依赖

| 参与方 | 职责 |
| --- | --- |
| Vue 房间页 | 复用 `withAccess` 发起 HTTP 请求，管理连接、发送状态、重连和右侧列表。 |
| `liveflow-api` | 提供两个 MVC 入口和 WebSocket 入口，负责 HTTP 与消息帧编解码、连接注册注销、按连接串行写入。 |
| `liveflow-core` | 校验房间和正文，读取已认证发送者的显示名，负责账号额度、短期去重和提交接受规则，通过广播接口交给本机连接管理。 |
| `liveflow-infrastructure` | 使用 Redis 保存和原子消费 Ticket，复用既有当前会话校验。 |
| MySQL 与 JVM | MySQL 提供房间信息与用户资料。JVM 保存连接、限流计数和短期提交记录，弹幕消息在内存中分发。 |

跨层方法和前端请求入口说明职责、参数、返回值及适用异常。关键注释解释 Ticket 的单次消费、受理与分发的顺序，以及连接队列满后的处理。

## 端到端流程

### 申请票据并加入房间

1. 房间详情加载成功后，Vue 用当前会话申请该房间的 Ticket。服务端验证房间和当前账号，签发一次性票据。
2. 浏览器打开 `/ws/rooms`。握手通过来源校验后，浏览器在首帧通过 `auth` 提交 Ticket。后端消费票据并重新确认绑定的登录会话。
3. 服务端先将 `ready` 放入连接的发送队列，再让连接参与房间广播。Vue 收到 `ready` 后启用发送。房间页的标题、分享和返回操作独立于弹幕连接。 [连接协议](api.md#websocket-接收协议)

### 发送并展示

1. 用户提交正文，Vue 固定本次输入快照并生成 `clientMessageId`。同一提交等待结果期间禁用重复提交。
2. MVC 验证当前会话、CSRF 和房间。业务层规范化输入，先检查是否已接受相同提交，再为新提交读取发送者显示名。受理时重新裁决去重与限流，在房间内确定顺序，由本机连接管理将带显示名的消息放入各连接队列。 [提交裁决](storage.md#提交裁决与广播顺序)
3. HTTP 成功后清理与本次提交对应的输入，列表只在收到 `message` 后追加。广播与响应的到达先后由各自传输链路决定。收到超过 100 条时移除最早的条目。
4. 输入或额度错误保留输入，提示原因。请求超时或响应丢失时保留输入快照和原 ID，并提示结果不确定。用户主动重试原正文时复用该 ID，修改正文后重新发送使用新 ID。重连流程不自动重发弹幕。 [发送契约与错误](api.md#发送弹幕)

### 断线、换房和退出

1. 短时断线时禁用发送，页面保留已收到的列表。重连使用新 Ticket，重新收到 `ready` 后启用发送。
2. 退出、会话替换、房间切换或页面卸载时停止旧连接及其重连任务。切换后清理列表和待发送状态。迟到的消息和 HTTP 结果只作用于对应的房间、连接与会话。
3. 页面刷新后重新建立连接并从空列表开始。刷新时可重新查看当前房间详情。

## 弹幕面板

- 消息头部展示浏览器本地时间，格式为 24 小时制 `HH:mm:ss`。前端按 WebSocket 到达顺序追加，同一秒内的消息仍显示为独立条目。
- 每条消息先显示固定宽度的等宽数字时间，右侧将浅绿加粗的发送者名称、分隔符及正文放在同一行。空间不足时自然换行，续行与名称及正文所在内容区域左对齐。用断词处理连续长文本，避免面板横向滚动。发送者名称和正文使用 Vue 纯文本渲染。
- 面板顶部显示连接状态，底部发送区固定在面板内部，中间列表独立滚动。连接断开时保留已接收消息和输入草稿，在状态区提供「重连」。发送校验、频率限制和提交失败提示放在发送区。输入法组字期间按 Enter 会保留输入法行为。
- 用户位于底部时，新消息到达后跟随滚动。用户向上阅读时保持当前阅读位置，并显示「查看新消息」，点击后回到底部。列表最多保留最近 100 条，裁剪时尽量保持仍可见的消息位置。

## 异常、并发与恢复

| 场景 | 裁决与用户可见行为 |
| --- | --- |
| 相同提交重试 | 当前实例仍保有记录时，相同规范化正文返回原结果。正文不同返回冲突。 |
| 已发送但 HTTP 响应丢失 | 页面提示结果不确定，按原 ID 手动重试。记录过期或实例重启后，重新提交可能再次广播。 |
| 同账号多标签页或跨房间发送 | 共享同一账号滚动额度。重复命中已接受记录时沿用原结果。 |
| 会话失效 | HTTP 按现有认证契约拒绝。接收连接在下一次服务端复查执行时确认并关闭。 |
| 慢连接或网络写入失败 | 关闭并清理该连接。其他连接继续按各自队列发送。 |
| 票据或认证依赖故障 | 暂停弹幕连接或发送。房间详情按既有 HTTP 契约处理。 |
| 发送者资料读取失败 | 尚未接受的提交返回弹幕服务暂不可用，保留输入以便重试。 |
| 应用回退或重启 | 活跃连接关闭，内存状态释放。页面重新建立连接后只接收后续消息。 |
