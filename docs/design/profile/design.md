# 个人主页 V1 设计

## 背景、目标与范围

认证成功后进入个人主页，用户可查看和编辑本人的昵称、预设头像和个人简介，也可从主页退出登录。已有账号第一次访问时可以直接使用默认资料。资料保存成功后，刷新页面仍可看到保存结果。 [当前登录视图](../../../frontend/src/auth/AuthView.vue) · [登录认证设计](../auth/design.md)

首版沿用 `/` 作为入口。页面面向当前登录用户，用户 ID 仅用于内部识别。对外公开的用户主页和自定义头像上传归入后续阶段。「我的直播间」由房间模块提供，个人主页承载创建与进入入口。 [直播间 V1 设计](../room/design.md)

## 方案选择与设计思路

- **登录身份与展示资料各有归属。** 账号使用稳定的 `userId`，用户名继续用于登录。昵称是可编辑的展示资料，允许重名。房主归属使用账号 ID，改昵称后房主关系仍然有效。 [房间数据归属](../room/database.md#数据归属与访问场景)
- **已有账号使用默认资料。** 资料表以账号 ID 为主键。读取时可由账号生成默认展示，首次保存时才创建资料行。这样旧账号可以直接进入主页，账号初始化和认证链路继续按现有设计运行。
- **首版采用预设头像。** 数据库保存头像标识，Vue 从内置资源渲染头像。前后端使用同一份标识约定，具体取值见 [HTTP 接口](api.md#更新资料)。
- **一次提交保存整份表单。** 用户同时提交昵称、头像和简介。后端规范化并校验所有字段，再原子保存这一组值。并发编辑采用最后一次成功提交的整份资料。

## 模块分工与依赖

| 参与方 | 职责 |
| --- | --- |
| Vue 个人主页 | 与登录表单共用一份 `useAuth` 状态。展示资料和退出入口，提供编辑、保存和取消，保留失败时的表单内容。 |
| `liveflow-api` | 增加认证路由、资料 Controller、请求和响应 DTO、错误映射。由安全过滤链验证 Bearer 和适用的 CSRF，从已验证 JWT 取得账号 ID。 |
| `liveflow-core` | 增加资料 Service、Mapper 和 Flyway 迁移。负责规范化与校验、默认资料组装、保存和事务内回读。 |
| MySQL | `users` 提供账号标识与用户名，`user_profiles` 保存用户编辑的资料。 |
| 认证会话 | 沿用 Redis 当前会话校验。会话被替换或撤销后，后续资料请求按现有鉴权规则处理。 |

实现时为 Java 跨层方法和前端请求入口补充职责、参数、返回值及适用的错误说明。关键注释说明默认资料回退、写入前校验和并发保存的裁决依据。

## 端到端流程

### 登录并查看主页

1. 用户打开 `/`。前端先完成现有会话恢复。缺少有效会话时显示登录表单。登录或恢复成功后，使用 `GET /api/v1/auth/me` 建立当前页面身份。 [当前用户接口](../auth/api.md#当前用户)
2. 前端进入个人主页并请求资料。资料加载期间显示加载状态。后端从认证身份读取账号，通过资料接口返回用户名、显示名、头像和简介。
3. 账号尚未保存资料时，页面使用用户名作为显示名，展示默认头像和空简介。资料已保存时展示正确的资料。读取失败时保留当前登录状态，服务暂不可用的情况提供资料重试入口。

### 编辑并保存

1. 用户点击「编辑资料」，用当前资料初始化表单。取消时丢弃本次输入，恢复到最近一次成功加载的资料。
2. 用户提交后，前端在请求处理期间禁用保存按钮，以当前会话的 Access Token 和 CSRF 请求头提交完整表单。
3. 后端校验身份和输入，在同一事务中写入并回读资料。提交成功后返回规范化结果，前端用响应更新展示并退出编辑状态。
4. 字段校验或保存失败时，页面保留表单并提示原因。发生超时且结果无法确认时，用户可以先重新读取服务端资料，再决定是否重新提交。

## 失败、并发与兼容

| 场景 | 处理方式 |
| --- | --- |
| Access Token 过期 | 沿用现有同会话续期机制。仅当服务器明确拒绝过期票据时，续期成功后重发一次原请求。 |
| 退出、被替换或切换登录会话 | 清除原会话的资料与编辑状态。前端收到迟到响应时核对会话归属，只用当前会话的结果更新页面。 |
| 两个标签页同时首次保存 | MySQL 主键裁决，最终只有一行。每次成功保存提交一份完整资料，最后一次提交决定最终值。其他标签页重新读取后看到数据库中的结果。 |
| 资料读取或写入依赖故障 | 区分认证和资料存储故障，页面按接口错误处理。明确的事务失败回滚。响应超时通过重新读取确认。 |
